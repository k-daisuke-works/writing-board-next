# 完了パイプライン（検証 → コミット → プッシュ）

## 1. 検証（変更内容に応じて選択）

| 変更内容 | 検証方法 |
|---|---|
| 1〜2ファイルの小変更 | `npx tsc --noEmit` を直接実行 |
| 複数ファイル・設定/依存変更 | **build-check エージェント**（haiku）に委譲 |
| Server Action・DBクエリ・API追加/変更 | **tenant-audit エージェント**（sonnet）で監査 |
| TSXコンポーネント追加/変更 | **mobile-review エージェント**（haiku）で監査 |

- 監査エージェントの🔴指摘は修正してからコミットする。🟡は判断してユーザーに報告
- 独立したエージェントは並列に起動してよい

## 2. コミット

1. `git status` で変更ファイルを確認（意図しないファイルの混入がないか）
2. `*.log`・一時ファイル・`.env*` はステージしない
3. `git add <変更ファイルを明示>`（`git add .` は使わない）
4. コミットメッセージ: `feat:` / `fix:` / `chore:` / `refactor:` プレフィックス＋何を・なぜ（日本語可）。末尾に Co-Authored-By（現在使用中のモデル名）

## 3. プッシュ

`git push origin master` → 完了をユーザーに報告。
DBマイグレーションを含む場合は「Supabase SQL Editor での実行が必要」も必ず添える。
